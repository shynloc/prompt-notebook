# 统一设置与 AI 提示词分析设计

## 决策

桌面侧栏只保留一个“设置”入口。`/settings/ai` 与 `/settings/storage` 继续作为可深链页面，共享设置页标题和横向 Tab；`/settings` 重定向到 AI 模型页。移动端从“我的”进入设置，不增加底部导航密度。

提示词百科增加“AI 提示词分析”Tab。它是一次性结构化分析工作台，不是开放式聊天：用户粘贴完整 Prompt，AI 只提取原文已有的高价值词汇、词组和短句，按既有百科分类返回。候选项先选择和编辑，再批量收录，绝不点击即写入。

## 数据流

1. `POST /api/v1/terms/analyze` 校验 Prompt、认证用户并执行限流。
2. 使用用户指定的“词库分析”模型；未指定时继承提示词优化模型。
3. OpenAI-compatible Adapter 返回 JSON 文本，服务端剥离常见代码围栏并以 Zod 严格校验。
4. 服务端验证候选内容确实来自原文，限制数量和长度，然后与内置词库及用户词库执行规范化和相似度去重。
5. 前端按分类展示候选标签、置信度和重复提示，允许选择、修改名称、内容与分类。
6. `POST /api/v1/terms/bulk` 在单次请求中批量保存，唯一约束和请求内去重共同阻止重复写入。

## 模型配置

`term_analysis` 是一种模型用途，不新增模型能力。它要求模型具备 `prompt_optimization` 文本能力。AI 设置页增加“词库分析模型”选择器；未设置时分析服务自动回退到提示词优化模型，避免强迫用户重复配置。

## 体验与异常

- 分析期间显示“理解内容、分类、检查重复”的循环阶段提示，不显示虚假百分比。
- 剪贴或请求失败不清空输入；支持重试。
- 完全重复项禁用并标记“已收录”；疑似重复项默认不选但允许人工确认。
- 批量保存期间禁用操作，成功后把已保存候选标记为“已收录”。
- 未配置模型时给出设置页入口；供应商错误继续使用现有脱敏错误体系。
- 桌面采用输入区与结果区布局，移动端改为纵向分组和底部批量操作栏。

## 验证

- 单元测试：JSON 解析、原文约束、规范化和相似度去重。
- 集成测试：模型继承/覆盖、账户隔离、批量保存和重复跳过。
- 组件测试：Tab、分析状态、选择、编辑、批量保存和错误恢复。
- E2E：配置模型、分析 Prompt、选择候选并在百科中找到新词条。
