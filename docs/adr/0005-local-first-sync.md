# ADR-0005：采用本地优先草稿与同步 outbox

## Status

Accepted — 2026-07-19

## Context

当前 Demo 的问题之一是浏览器数据会丢失，但完全依赖网络也会让编辑体验变慢，并在断网、登录过期或数据库故障时丢失输入。项目还希望游客无需注册即可试用。

## Decision

使用 IndexedDB 保存游客实体、当前草稿和待同步操作。用户输入先本地提交，再通过 outbox 异步写服务端。服务端使用 UUID、幂等键和整数版本实现去重与乐观并发控制。

登录时先展示本地到云端的迁移预览，再执行幂等合并；不静默覆盖云端记录。

## Consequences

### Positive

- 输入得到即时反馈，刷新、断网和短期服务故障不丢失草稿。
- 游客可以完整体验核心价值。
- 同步失败可观测、可重试。

### Negative

- 增加双存储、队列、冲突和模式迁移复杂度。
- 需要测试浏览器存储配额、隐私模式和多标签页。
- 本地数据不能替代服务端备份。

### Neutral

- MVP 不做字符级实时协作；冲突以记录版本为单位处理。

## Alternatives Considered

- **仅服务端保存**：实现简单，但弱网编辑体验和输入可靠性不足。
- **继续 localStorage**：容量、事务和结构化查询能力不足。
- **完整 CRDT**：协作能力强，但当前没有多人实时编辑需求。
- **每次按键同步服务端**：请求量大且离线表现差。
